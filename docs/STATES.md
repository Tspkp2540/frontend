# Frontend states และการกู้คืน

ตรวจ flow ปกติควบคู่กับ failure paths; ปุ่มลองใหม่ทำเฉพาะการอ่านข้อมูล ไม่ส่งจองซ้ำอัตโนมัติ

| Flow / สถานะ | สิ่งที่ผู้ใช้เห็น | ทำต่ออย่างไร |
|---|---|---|
| ตรวจ session | ข้อความกำลังตรวจสอบ | สำเร็จแล้วเปิดหน้าที่ขอ; ไม่มี session กลับ login |
| ตรวจ session ไม่สำเร็จ | หน้าข้อผิดพลาด | ลองใหม่ |
| สมัคร / login ผิดหรือเชื่อมต่อไม่ได้ | Error ในฟอร์ม เก็บค่าที่กรอก | แก้ข้อมูลหรือส่งใหม่; 429 แสดงเวลารอ |
| โหลดรายการห้อง | Skeleton | รอผล ไม่แสดงข้อมูลว่างระหว่างโหลด |
| ไม่มีห้องเปิดรับจอง | Empty state | ลองใหม่หรือกลับมาภายหลัง |
| รายการห้องโหลดไม่ได้ / response ผิดรูปแบบ | หน้าข้อผิดพลาด | ลองใหม่ |
| รูปโหลดไม่ได้ | ภาพแทนพร้อมข้อความ | ยังเลือกห้องและจองได้ |
| ไม่พบห้อง / URL | หน้าห้องไม่พบ / หน้าไม่พบ | กลับหน้าห้องพัก; ห้องไม่พบตรวจใหม่ได้ |
| ปฏิทินโหลดครั้งแรกไม่สำเร็จ | Error และไม่มีปุ่มยืนยันจอง | ลองใหม่หรือเลือกห้องอื่น |
| เปลี่ยนเดือนแล้วโหลดไม่สำเร็จ | Error เก็บข้อมูลผู้เข้าพัก ปิดการจอง | ลองใหม่; สำเร็จแล้วจึงจองได้ |
| ไม่มี booking ในเดือน | ปฏิทินปกติ มีวันว่าง | เลือกวันเข้า/ออก |
| ไม่มีคืนว่างในช่วงที่แสดง | ข้อความแจ้งเต็ม | เปลี่ยนเดือนหรือเลือกห้องอื่น |
| วันพักไม่ถูกต้อง / ข้อมูลผู้เข้าพักผิด | Error ข้าง field หรือฟอร์ม | แก้ข้อมูลก่อนยืนยัน |
| กำลังบันทึก | ปุ่ม busy; ปิด Dialog และส่งซ้ำไม่ได้ | รอผล |
| วันชนระหว่างยืนยัน | แจ้ง conflict เก็บข้อมูลผู้เข้าพัก ล้างวันที่ | อัปเดตปฏิทินแล้วเลือกวันใหม่ |
| จองสำเร็จ แต่ refresh ปฏิทินล้มเหลว | Receipt คงอยู่ พร้อม calendar error | ลองโหลดปฏิทินใหม่ ไม่ส่งจองซ้ำ |
| ส่งจองแล้ว network ขาด / timeout / 5xx | แจ้งว่ายังยืนยันผลไม่ได้ | ตรวจผลด้วย key หรือส่ง payload/key เดิมซ้ำ; ไม่สร้าง booking เพิ่ม |
| Reload ระหว่างไม่ทราบผล | ตรวจ key เดิมอัตโนมัติ | พบแล้วแสดง receipt; lookup ล้มเหลวลองใหม่ได้; ยังไม่พบให้ตรวจซ้ำหรือกรอกข้อมูลเดิมส่งด้วย key เดิม |
| Session หมดอายุ | Dialog กลาง | กลับ login |
| Logout ไม่สำเร็จ | Error บนหน้าเดิม | ลอง logout อีกครั้ง |
| API ไม่ตอบภายใน 15 วินาที | Timeout error | ลองใหม่ตามประเภทคำขอ |
| Render error / lazy page โหลดล้มเหลวหรือเกิน 15 วินาที | หน้ากู้คืน | โหลดหน้าใหม่หรือกลับหน้าห้องพัก |

## หลักฐาน

75 unit/component tests และ 27 browser flows ตรวจ success/recovery, timeout/cancellation, malformed responses, empty state, auth, conflict, session, รูปเสีย, URL ไม่พบ, pending action, receipt หลัง refresh error และ idempotent recovery ดู [งาน 07](TESTING.md) และ [งาน 09](TESTING.md)

Backend เพิ่ม migration 003 และ endpoint ตรวจผล; ล่าสุด 176 tests ผ่าน

## ข้อจำกัดที่ควรรู้

Key เก็บใน sessionStorage แยกตามผู้ใช้/ห้อง ไม่มีข้อมูลผู้เข้าพัก เมื่อสำเร็จลบ key; ปิดแท็บหรือ storage ถูกปิดอาจกู้ key หลัง reload ไม่ได้ ขณะยังอยู่ในแอปมี memory fallback ไม่ใช้การส่งซ้ำอัตโนมัติ หาก reload แล้วยังไม่มีผล ผู้ใช้กรอกข้อมูลเดิมใหม่โดยคง key เดิมไว้ ผล lookup 404 ไม่ได้ยืนยันว่า transaction ล้มเหลว

Error boundary รองรับข้อผิดพลาดระหว่าง render และ lazy page หลังโหลดแอปแล้ว หากดาวน์โหลดไฟล์เริ่มต้นของเว็บไม่ได้เลย ผู้ใช้ยังต้องใช้หน้า error/reload ของ browser
